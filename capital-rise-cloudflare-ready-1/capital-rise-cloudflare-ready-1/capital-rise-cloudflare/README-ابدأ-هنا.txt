CAPITAL RISE — نسخة Cloudflare Pages + D1
========================================
هذه النسخة تحافظ على قالب واجهة الموقع الأصلي وتحوّل الخلفية إلى Cloudflare Pages Functions + D1 بدل خادم Node.js.

قبل النشر:
- لا ترفع ملف .env أو ملف LOGIN-دخول-الادمن.txt. لم يتم تضمينهما هنا.
- لوحة الأدمن: /admin/ ، صفحة الدخول: /admin/login.html
- اسم المستخدم الافتراضي: admin
- كلمة المرور تضبطها أنت كـ Cloudflare Secret باسم ADMIN_PASSWORD، ولا توجد كلمة مرور ثابتة داخل الملفات.
- رقم واتساب الافتراضي الموجود في المشروع: 971541494114 ويمكن تغييره من لوحة الأدمن.

خطوات النشر (تحتاج حساب Cloudflare مجاني):
1) فك ضغط الملف ZIP على الكمبيوتر.
2) افتح dash.cloudflare.com وأنشئ D1 Database باسم capital-rise-db.
3) افتح قاعدة البيانات ثم Console ونفّذ محتوى migrations/0001_init.sql بالكامل.
4) من إعدادات D1 انسخ Database ID وضعه بدل REPLACE_WITH_YOUR_D1_DATABASE_ID في wrangler.toml.
5) ارفع المجلد إلى مستودع GitHub خاص، أو استخدم طريقة رفع ملفات Pages المتاحة في حسابك. إذا استخدمت Git integration اختر جذر المشروع هذا كمجلد النشر، ولا تضع المشروع داخل مجلد فرعي آخر.
6) أنشئ Pages project واربطه بالمستودع. Build command: اتركه فارغًا. Build output directory: .
7) في إعدادات المشروع > Functions > D1 database bindings، أضف Binding باسم DB واربط قاعدة capital-rise-db.
8) في Settings > Variables and Secrets أضف Secret باسم ADMIN_PASSWORD بقيمة كلمة مرور قوية لا تقل عن 12 حرفًا، وأضف Variable باسم ADMIN_USERNAME وقيمته admin.
9) أعد النشر Deploy، ثم اختبر رابط pages.dev أولًا.
10) اختبر الموقع العام، ثم افتح /admin/login.html وسجّل الدخول. بعد أول دخول، غيّر كلمة المرور من تبويب إعدادات التواصل / كلمة مرور لوحة التحكم.
11) بعد نجاح الاختبار، أضف الدومين من Pages > Custom domains واتبع سجلات DNS التي يعرضها Cloudflare حرفيًا داخل لوحة Hostinger. لا تخمّن سجلات DNS.

ملاحظات مهمة:
- لا يمكنني الدخول إلى حساباتك أو تنفيذ إنشاء قاعدة البيانات/الأسرار/تعديل DNS نيابة عنك، لذلك هذه الإعدادات لا يمكن تضمينها في ZIP.
- تخزين صور الشهادات في D1 بهذه النسخة محدود بحوالي 1.4MB لكل صورة لتجنب حدود حجم الصف؛ اضغط صور الشهادات قبل رفعها.
- بعد إعداد D1 وربط binding باسم DB، بيانات الخدمات والشهادات والإعدادات والجلسات تُحفظ في قاعدة البيانات بدل LocalStorage.
- إذا فشل API بعد النشر، راجع أن Binding اسمه بالضبط DB وأن الـ migration نُفذ على قاعدة البيانات نفسها المرتبطة بالمشروع.
